# GDM — Gamepad Device Manager

Nueva base de GDM para Windows, creada con .NET 10 y WPF. La aplicación usa un único proyecto de producción; el proyecto de pruebas permanece separado.

## Estructura

- `App.xaml` y `App.xaml.cs`: inicio y recursos globales de WPF.
- `Views`: ventanas y vistas XAML.
- `ViewModels`: estado y navegación que consume la interfaz.
- `Models`: modelos y reglas de los datos de GDM.
- `Services/Abstractions`: contratos entre la aplicación y sus servicios.
- `Services/Persistence`: almacenamiento local JSON.
- `Services/Sdl2GamepadDetectionService.cs`: detección de dispositivos conectados mediante SDL2.
- `ThirdParty/SDL2/2.32.10`: runtime nativo SDL2 actualizado para exponer `SDL_JoystickPath`, requerido por la integración de HidHide. Se incluye el aviso de distribución oficial de SDL.
- `Services/HidMaestroGamepadMapper.cs` y `HidMaestroVirtualGamepadService.cs`: traducción de entradas SDL y salida virtual.
- `ThirdParty/HIDMaestro/2.1.0`: SDK local HIDMaestro y avisos/licencias.
- `tests`: pruebas automatizadas.
- `bin`: ejecutable compilado, dentro de `Debug` o `Release`.

La interfaz marca explícitamente como pendientes las funciones que todavía no están implementadas. SDL2 detecta y actualiza la lista de dispositivos conectados y accesibles al abrir Mandos y mediante reconciliación periódica. La pestaña `HidHide` permite ocultar una interfaz HID mientras GDM está abierto, agregándola a la lista negra persistente de HidHide. GDM registra primero las entradas que agrega, restaura solo esas entradas al cerrar normalmente y las recupera al siguiente inicio tras un cierre inesperado; si la restauración falla, informa y pide confirmación antes de cerrar, conservando el diario para el siguiente intento. Las entradas preexistentes, la lista global de aplicaciones permitidas y el filtro global no se eliminan ni cambian (salvo agregar GDM a la lista permitida si hace falta). El diario de recuperación se guarda en `%LocalAppData%\GDM\HidHide`. El driver HidHide se instala por separado; GDM no lo redistribuye. Desde Mandos se pueden guardar y eliminar registros; los mandos guardados permanecen visibles desconectados. Al reconectar, GDM prioriza el número de serie único. Si SDL no lo proporciona, solo asocia el registro cuando coinciden exactamente el nombre y VID/PID, y hay un único registro guardado y un único mando conectado que encajan; si existen varios candidatos, los deja separados. Esta coincidencia reconoce el modelo, pero no demuestra que sea la misma unidad física: SDL puede no distinguir mandos idénticos sin un número de serie. El ID de instancia SDL no se usa como identidad persistente. La pestaña `Perfiles` permite crear, renombrar, duplicar y eliminar perfiles JSON, asignarlos a mandos guardados y editar sus mapas de botones y ejes para la salida virtual. También sigue pendiente la consulta de dispositivos emparejados/cercanos de Windows.

La versión actual de GDM es **0.3.0**. El primer número cambia ante una renovación drástica del programa; el segundo, cuando se incorporan una o más funciones nuevas desde la versión anterior; el tercero aumenta por cada arreglo de un problema ya existente. Se contabilizaron 20 correcciones distintas documentadas en el historial disponible para establecer el número inicial. La versión aparece como `VERSIÓN` en la esquina superior derecha y en Acerca de. También se muestra un ID corto derivado del módulo y la fecha/hora local de modificación del ejecutable; estos identifican el artefacto compilado, no una versión nueva.

La versión 0.1.31 amplió el registro de HidHide: documenta la ruta de GDM y el estado de su lista permitida al ocultar, y comprueba la lista negra tras ocultar o mostrar un mando. La versión 0.2.0 agregó en la pestaña `Mandos` el botón `Dispositivos de juego`, que abre la herramienta nativa de Windows para probar mandos (`joy.cpl`). En `Perfiles`, cada mando guardado también permite elegir `Mantener oculto al cerrar GDM`; al activarlo, GDM conserva la entrada administrada en HidHide al cerrar y la deja oculta en los siguientes inicios hasta que se muestre desde la pestaña HidHide.

Al iniciar una instancia nueva, GDM abre en `Inicio`. Si ya hay una instancia en ejecución (incluida la bandeja), una nueva solicitud restaura esa misma ventana y conserva la pestaña que estaba seleccionada.

GDM permite una sola instancia por usuario y sesión de Windows. Si se vuelve a abrir, la segunda ejecución muestra un aviso y solicita a la instancia existente que muestre y restaure su ventana, incluso si estaba minimizada en la bandeja o en la barra de tareas. El inicio elevado interno de un mando virtual transfiere el turno a la instancia elevada para conservar este comportamiento. La pestaña `Ajustes` organiza las opciones en General, Interfaz, Mandos, Dependencias y Acerca de. Permite seleccionar los temas Sistema, Claro y Oscuro, configurar opcionalmente el inicio con Windows y el inicio minimizado en la bandeja, y elegir el inicio elevado mediante una tarea programada. La opción de tarea requiere autorización de administrador al activarla, actualizarla o quitarla; después Windows inicia GDM con privilegios elevados al iniciar sesión sin solicitar UAC en cada inicio. El modo normal usa la clave Run del usuario actual y no requiere elevación. Las preferencias se guardan en JSON y se pueden restaurar a valores predeterminados conservando el tamaño de ventana. Sistema sigue la preferencia de aplicaciones de Windows; si el valor del sistema no está disponible, se usa el tema claro. Al cerrar la ventana, GDM permanece en la bandeja. El menú contextual del icono permite abrir GDM o cerrar el programa; cerrar desde la bandeja restaura los cambios administrados de HidHide. Si HidHide hace que SDL vuelva a enumerar un mando ocultado, la salida virtual se reasocia a la nueva instancia SDL cuando coinciden la ruta física o una identidad inequívoca del mando guardado. Mientras hay una salida virtual activa, GDM reconcilia dispositivos cada 500 ms (en lugar de cada 3 s) para reducir el intervalo en que el mando físico puede quedar desasociado tras la enumeración. GDM espera varios segundos antes de considerar que la lectura se perdió permanentemente. Los mandos guardados no se alteran al restablecer las preferencias. La interfaz solo está disponible en español; la opción de actualización automática todavía no tiene un servicio asociado y por eso no se presenta como un ajuste operativo.

La pestaña `Tester` lista los mandos SDL conectados y permite seleccionar uno con un clic (mantener y arrastrar por la lista no cambia la selección) para ver en vivo botones y ejes. SDL informa el recuento de ejes y botones físicos del joystick; para mandos mapeados también se muestran solo los ejes y botones lógicos que SDL reconoce. La lista estándar incluye controles extendidos disponibles en el mapeo, como palas y clic del panel táctil. El diagrama refleja L1/R1, L2/R2 analógicos, clics L3/R3, botones centrales y el panel táctil/botón extra cuando SDL lo mapea. Los mandos que SDL no reconoce como game controllers muestran índices físicos sin asumir un mapeo semántico. Se presenta la ruta, GUID, serial e IDs cuando SDL los proporciona. Firmware y batería se indican como no disponibles porque el servicio SDL actual no expone esos datos.

En `Perfiles`, cada mando físico guardado tiene controles independientes para iniciar o detener su salida virtual Xbox 360 con HIDMaestro. Es posible mantener varias salidas a la vez. Cada salida usa el perfil asignado a su mando: los botones y ejes remapeados se envían a sus destinos y los controles no editados conservan el mapeo estándar. La opción `Iniciar al conectar` se guarda por mando y activa su salida cuando GDM detecta ese mando; permanece sujeta a la asociación segura de identidad descrita arriba. `Ocultar automáticamente` también se guarda por mando y agrega el HID físico a la lista negra solo después de que su salida virtual se inicia correctamente. Durante el inicio de GDM, el ocultamiento automático queda pendiente hasta cargar perfiles y mandos, terminar los inicios automáticos y dar tiempo a que arranque la lectura de entradas; así los dispositivos físicos permanecen visibles mientras se preparan las salidas virtuales. Al detener la salida, GDM vuelve a mostrar el mando que ocultó automáticamente. Si SDL deja de enumerar temporalmente el mando oculto, GDM comprueba la presencia del dispositivo HID en Windows: si sigue conectado, mantiene viva la salida y su asociación para evitar un ciclo de reconexión; si Windows confirma su desconexión en tres comprobaciones separadas, GDM detiene la salida y limpia el ocultamiento. Si Windows confirma que el mando sigue conectado pero SDL no entrega entradas durante tres comprobaciones separadas, GDM lo vuelve a mostrar y pausa el ocultamiento automático de ese mando hasta cerrar GDM, para evitar dejar una salida virtual sin respuesta. Su fila permanece en HidHide para poder mostrarlo manualmente. Los controles sin mapeo estándar de SDL no se emiten. Al iniciar desde GDM sin elevar, se pide confirmación y UAC, y se vuelve a abrir GDM como administrador. HIDMaestro instala su controlador la primera vez que se activa una salida. El sondeo se realiza cada 8 ms mientras haya salidas activas. La vibración y la transferencia de sensores aún no están implementadas. La emulación real debe probarse con hardware y Windows compatibles.

La pestaña `Perfiles` mantiene perfiles reutilizables en `%LocalAppData%\GDM\Profiles`. La eliminación se bloquea mientras un perfil esté asignado; primero hay que reasignar esos mandos o seleccionar `Sin perfil`. Los perfiles editan mapas de botones y ejes, inversión de cada eje de stick y zonas muertas de ambos sticks. Estos cambios se aplican solo al mando virtual del mando físico al que se asignó el perfil; no afectan a la entrada física ni remapean juegos directamente. Las preferencias para iniciar automáticamente la salida y ocultar el mando físico después de iniciarla se guardan por mando.

La integración con HidHide usa las IOCTL de lista negra persistente compatibles con el controlador estable. El modo global de HidHide debe estar activo y la lista de aplicaciones no debe estar invertida. Antes de inicializar SDL2, GDM se asegura de estar en la lista de aplicaciones permitidas para que el filtrado del mando físico no interrumpa la lectura de entrada del propio GDM. Antes de agregar una interfaz HID a la lista negra, GDM guarda un diario local; al cerrar normalmente quita únicamente las entradas que él agregó y al siguiente inicio recupera cambios pendientes. Un cierre forzado puede dejar el mando oculto hasta que GDM se vuelva a iniciar; no hay forma de garantizar la restauración inmediata tras una caída del proceso o del sistema. Mientras GDM está abierto, los mandos que ocultó se conservan en Mandos, Tester, Perfiles e HidHide siempre que Windows confirme que siguen conectados, aunque SDL deje de enumerarlos. La inclusión en la lista no garantiza que SDL pueda leer sus entradas: si no aparecen datos, verifica que GDM esté permitido en HidHide. Antes de cada actualización, GDM vuelve a leer la lista negra y conserva las demás entradas observadas. Si se agrega GDM a la lista permitida, esa autorización permanece hasta quitarla desde la herramienta oficial de HidHide. El controlador debe estar instalado y activo. La ruta de dispositivo usada para ocultar es la interfaz HID que SDL expone para ese mando. Para ello GDM distribuye el runtime oficial SDL 2.32.10, ya que el SDL 2.0.20 incluido originalmente no exportaba `SDL_JoystickPath`. Mandos compuestos pueden requerir configurar interfaces adicionales en HidHide. La integración debe validarse con un mando real y el controlador instalado.

## Compilar y probar

Desde esta carpeta:

```powershell
dotnet build GDM.sln
dotnet test GDM.sln
dotnet run --project GDM.csproj
```

El ejecutable se genera en `bin/Debug/GDM.exe` al compilar en modo Debug. GDM se distribuye como aplicación portable: copia la carpeta completa de salida, no solo el `.exe`, ya que allí están las dependencias necesarias.

El equipo necesita tener instalado por separado el **.NET 10 Desktop Runtime x64**. SDL2 y `HIDMaestro.Core.dll` se incluyen como dependencias junto a GDM en la carpeta de salida, con sus archivos de licencia/avisos. HIDMaestro instala su controlador bajo consentimiento UAC la primera vez que se inicia la emulación; no se instala ni se elimina automáticamente al copiar o borrar GDM.

## Decisiones iniciales

- UI: WPF; ventanas y lógica de presentación se organizan en carpetas distintas.
- Organización: un solo proyecto de producción con carpetas por categoría, más un proyecto de pruebas.
- Framework: .NET 10 LTS.
- Persistencia prevista: JSON con `System.Text.Json`; no se usa SQLite.
- SDL: SDL2 mediante `Sayers.SDL2.Core` 1.0.11, con binarios nativos de Windows x64 incluidos por el paquete. Se utiliza para enumerar mandos y leer sus controles mapeados; no enumera emparejados o dispositivos Bluetooth cercanos.
- Salida virtual inicial: HIDMaestro 2.1.0, consumido desde el SDK local en `ThirdParty/HIDMaestro/2.1.0`; conservar `LICENSE` y `THIRD-PARTY-NOTICES.txt` al redistribuir. El primer destino es un mando Xbox 360 por cable.
- El paquete SDL proporciona binarios nativos x64; la aplicación actual se compila para Windows x64.
- Datos de usuario: `%LocalAppData%\\GDM`, bajo `Settings`, `Controllers`, `Profiles` y `Logs`.
- Los registros de mandos se escriben en `Controllers\controllers-index.json` y en un JSON individual `controller_<id>.json`. Guardar conserva la identidad y los campos de configuración actuales.
- Los perfiles se guardan en `Profiles\profiles-index.json` y en un JSON individual `profile_<id>.json`; la asignación del perfil queda en el `ProfileId` del mando guardado.
- Los ajustes aceptan los temas `System`, `Light` y `Dark`; valores no compatibles se reportan y el archivo se conserva sin sobrescritura.
- La pestaña `Registro` muestra errores y eventos de ejecución; el archivo se guarda en `%LocalAppData%\GDM\Logs\gdm.log`. Los errores de compilación deben consultarse en la salida de compilación de VS Code, ya que ocurren antes de iniciar la aplicación.
- La ventana inicia en 800 × 600 y guarda/restaura su último tamaño normal al cerrar y volver a abrir.
- La persistencia versiona los esquemas, escribe mediante un archivo temporal y reporta JSON dañado o versiones incompatibles en lugar de reemplazarlos silenciosamente.
- Cada mando guardado tiene un JSON individual y el catálogo usa nombres de archivo derivados del ID interno, no del nombre visible.

La identidad de un mando entre USB y Bluetooth depende de los identificadores expuestos por el dispositivo y Windows. GDM no debe asociar ni aplicar perfiles automáticamente cuando la evidencia no sea suficientemente fiable.
